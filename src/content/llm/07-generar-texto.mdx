El modelo entrenado da, para cada contexto, una distribución sobre los 2.048 tokens. Generar texto es elegir uno, añadirlo y repetir. Cómo se elige cambia muchísimo el resultado: quedarse siempre con el más probable produce bucles, y sortear sin más produce disparates. Las perillas que verás en cualquier API de LLM (**temperatura, top-k, top-p**) son las tres maneras de encontrar el punto medio.

## El bucle de generación

```python
@torch.no_grad()
def generate(model, idx, n, temperature=1.0, top_k=None, top_p=None, g=None):
    for _ in range(n):
        logits = model(idx[:, -CONTEXT:])[:, -1, :]     # solo la última posición: lo que viene ahora
        if temperature == 0:
            nxt = logits.argmax(-1, keepdim=True)       # greedy: siempre el más probable
        else:
            logits = logits / temperature
            if top_k is not None:                       # solo los k más probables
                kth = torch.topk(logits, top_k).values[:, -1, None]
                logits = logits.masked_fill(logits < kth, float("-inf"))
            probs = F.softmax(logits, dim=-1)
            if top_p is not None:                       # el conjunto más pequeño que suma top_p
                sorted_p, order = probs.sort(descending=True)
                sorted_p[sorted_p.cumsum(-1) - sorted_p > top_p] = 0
                probs = torch.zeros_like(probs).scatter(-1, order, sorted_p)
                probs /= probs.sum(-1, keepdim=True)
            nxt = torch.multinomial(probs, 1, generator=g)
        idx = torch.cat([idx, nxt], dim=1)
    return idx
```

- **Temperatura**: divide los logits antes del softmax. Por debajo de 1 concentra la probabilidad en los favoritos; por encima, la reparte.
- **Top-k**: solo pueden salir los $k$ tokens más probables.
- **Top-p** (*nucleus sampling*): solo el conjunto más pequeño de tokens cuya probabilidad suma $p$. Se adapta: si el modelo está seguro, quedan pocos; si duda, muchos.

<Callout kind="real" title="En el trabajo">
- **Valores habituales**: temperatura entre 0,7 y 1 y top-p entre 0,9 y 0,95. El valor por defecto depende de la API (varias usan temperatura 1 y top-p 1): revísalo. Para tareas con respuesta exacta (extraer datos, código, clasificar), temperatura 0 o muy baja.
- **Temperatura 0 no garantiza la misma respuesta siempre**: en GPU, el orden de las operaciones en paralelo cambia ligeramente los resultados, y un empate cercano puede resolverse distinto.
- **La velocidad de generación** depende de la caché de claves y valores, del tamaño del lote y de la cuantización. Nuestro GPT, sin caché: 166,6 tokens por segundo en MPS.

- Greedy repite; sortear sin control desvaría. Temperatura, top-k y top-p regulan el punto medio.
- Temperatura < 1 concentra, > 1 reparte. Top-k fija cuántos; top-p, cuánta probabilidad.
