Antes del transformer, el modelo de lenguaje más sencillo que existe: mirar solo el token anterior y contar. ¿Qué viene después de «don»? Casi siempre «Quijote». Un **modelo de bigramas** es una tabla de 2.048 × 2.048 con esas cuentas. No aprende nada en el sentido de una red, pero sirve para tres cosas: entender la pérdida que vas a minimizar, saber qué valores son buenos y tener un listón que el GPT tiene que batir.

## Contar y normalizar

Para cada token $a$, se cuenta cuántas veces le sigue cada token $b$ en el texto de entrenamiento, y se divide entre el total de la fila:

$$
P(b \mid a) = \frac{\text{cuenta}(a, b) + \lambda}{\sum_{b'} \big(\text{cuenta}(a, b') + \lambda\big)}
$$

El $\lambda$ (suavizado) evita probabilidades cero: una pareja que nunca salió en entrenamiento puede aparecer en validación, y $-\ln 0$ es infinito.

```python
counts = torch.zeros(VOCAB, VOCAB)
counts.index_put_((train[:-1], train[1:]), torch.ones(len(train) - 1), accumulate=True)
probs = (counts + 0.01) / (counts + 0.01).sum(dim=1, keepdim=True)
loss = -probs[val[:-1], val[1:]].log().mean()     # entropía cruzada media en validación
```

## La pérdida: entropía cruzada

La misma pérdida que en cualquier clasificador, y la misma que minimiza ChatGPT: el logaritmo negativo de la probabilidad que el modelo dio al token que de verdad vino, en media sobre todas las posiciones. Si el modelo acierta con probabilidad 1, vale 0. Si no sabe nada, reparte por igual.

<Callout kind="real" title="En el trabajo">
- **La perplejidad solo se compara con el mismo tokenizador.** Con tokens más largos, cada predicción es más difícil y la perplejidad por token sube, aunque el modelo sea igual de bueno. Para comparar modelos con tokenizadores distintos se usan bits por carácter o bits por byte.
- **Los n-gramas no han muerto.** Los modelos de n-gramas (con contextos de 3, 4 o 5 tokens) siguen siendo útiles para filtrar corpus enormes: se marcan como sospechosos los textos con perplejidad muy alta (basura) o muy baja (texto repetido).
- **El suavizado se elige con validación**, como cualquier hiperparámetro: aquí, el de 0,01 entre tres candidatos. Como se elige y se mide con el mismo bloque, la cifra es algo optimista.
</Callout>
