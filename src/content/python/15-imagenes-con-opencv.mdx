Para un ordenador, una imagen es **una matriz de números**: cada píxel, un valor de brillo (o tres, uno por canal de color). Así que todo lo que sabes de NumPy sirve para tratar imágenes: recortar es hacer *slicing*, aclarar es sumar, mezclar dos fotos es una media ponderada y detectar bordes es restar píxeles vecinos. **OpenCV** es la librería de referencia que hace todo eso rápido y añade lo que NumPy no tiene: leer formatos, filtros, detección de bordes y redes neuronales para detectar caras u objetos.

## Una imagen es un array

```python
import cv2
img = cv2.imread("meerkat.jpg")      # ndarray de forma (alto, ancho, 3), dtype uint8
img.shape, img.dtype                 # (750, 500, 3), uint8
img[100, 200]                        # un píxel: [B, G, R]  ← ¡en ese orden!
recorte = img[50:250, 100:400]       # recortar = slicing (es una vista)
gris = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)   # (750, 500): un solo canal
b, g, r = cv2.split(img)             # separar canales; cv2.merge([b, g, r]) los junta
```

- `uint8`: enteros de 0 a 255. Cero es negro; 255, el máximo de ese canal.
- OpenCV guarda los colores en orden **BGR**; matplotlib, PIL y casi todo lo demás, en **RGB**. Si una foto sale con la piel azulada, es eso.
- `cv2.imshow` abre una ventana (no funciona en Jupyter ni aquí); para mostrar, matplotlib con `plt.imshow(cv2.cvtColor(img, cv2.COLOR_BGR2RGB))`.

## Mezclar imágenes

El *blending* es una media ponderada píxel a píxel: $\text{resultado} = \alpha \cdot A + \beta \cdot B + \gamma$. Con $\alpha + \beta = 1$ se funden dos fotos (o se superpone un logo); es lo que hace `cv2.addWeighted(A, alpha, B, beta, gamma)`. Las dos imágenes deben tener la misma forma (si no, `cv2.resize` antes).

## Bordes: el gradiente de la imagen

Un borde es un sitio donde el brillo **cambia de golpe**. El **gradiente** mide ese cambio: el filtro de **Sobel** lo aproxima restando los píxeles de un lado menos los del otro (en horizontal, `dx=1`; en vertical, `dy=1`), y el **Laplaciano** usa la segunda derivada. **Canny** va más allá: suaviza, calcula el gradiente, adelgaza los bordes a un píxel y se queda con los fuertes y los débiles conectados a ellos (dos umbrales).

El detalle que el curso destaca: un borde de **oscuro a claro** da un gradiente positivo, pero uno de **claro a oscuro** da uno **negativo**. Si calculas Sobel directamente en `uint8` (`cv2.CV_8U`), los negativos se recortan a 0 y **pierdes la mitad de los bordes**. Lo correcto es calcular en `cv2.CV_64F` y tomar el valor absoluto.

## Detección de caras

El último ejemplo del tema usa una **red neuronal ya entrenada** (un detector SSD con ResNet, en formato Caffe) desde el módulo `cv2.dnn`. El patrón es el de cualquier modelo preentrenado: cargar, preparar la entrada como la espera la red, ejecutar y filtrar por confianza.

```python
net = cv2.dnn.readNetFromCaffe("deploy.prototxt.txt", "res10_300x300_ssd_iter_140000.caffemodel")
h, w = img.shape[:2]
# la red espera 300x300 y que se le resten las medias de cada canal con las que se entrenó
blob = cv2.dnn.blobFromImage(cv2.resize(img, (300, 300)), 1.0, (300, 300), (104.0, 177.0, 123.0))
net.setInput(blob)
detecciones = net.forward()                 # forma (1, 1, N, 7)
for i in range(detecciones.shape[2]):
    confianza = detecciones[0, 0, i, 2]
    if confianza > 0.5:
        x1, y1, x2, y2 = (detecciones[0, 0, i, 3:7] * [w, h, w, h]).astype(int)   # coordenadas relativas → píxeles
        cv2.rectangle(img, (x1, y1), (x2, y2), (0, 255, 0), 2)
```

## Para llevar

- Una imagen es un `ndarray` `uint8` de forma `(alto, ancho, canales)`; OpenCV usa BGR.
- En `uint8`, NumPy da la vuelta (250 + 10 = 4) y OpenCV satura (255): convierte a un tipo mayor o usa `cv2.add`.
- Mezclar es una media ponderada: `cv2.addWeighted`.
- Los bordes son gradientes: Sobel en `CV_64F` + valor absoluto, o Canny.
- Detectar con un modelo preentrenado: preparar la entrada como en el entrenamiento, ejecutar y filtrar por confianza.
