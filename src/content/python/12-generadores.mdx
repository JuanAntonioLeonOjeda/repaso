Un modelo de visión se entrena con cientos de miles de imágenes que no caben en la memoria. La solución es no cargarlas: **producirlas de una en una (o de lote en lote) justo cuando hacen falta**. Eso es un generador. Es una idea pequeña con un efecto enorme, y en los exámenes de la asignatura siempre cae una pregunta de «escribe un generador que…».

## Iterables, iteradores y yield

Un `for` funciona con cualquier **iterable**: le pide un **iterador** con `iter()` y luego llama a `next()` hasta que salta `StopIteration`. Una función con `yield` es una fábrica de iteradores:

```python
def cuenta_atras(n):
    while n > 0:
        yield n          # entrega un valor y se PAUSA aquí, con sus variables intactas
        n -= 1

g = cuenta_atras(3)      # no ejecuta nada todavía: crea el generador
next(g)                  # 3   (ejecuta hasta el primer yield)
next(g)                  # 2   (sigue desde donde se quedó)
list(g)                  # [1] (lo que queda)
next(g)                  # StopIteration: ya se agotó
```

Tres consecuencias:

- **Perezoso**: no calcula nada hasta que se lo piden. Un generador puede ser **infinito** (`while True: yield ...`) sin colgar el programa.
- **Memoria constante**: `sum(x * x for x in range(10**8))` no crea una lista de cien millones de elementos.
- **De un solo uso**: una vez agotado, hay que crear otro.

Las **expresiones generadoras** son comprehensions con paréntesis: `(x * x for x in datos if x > 0)`.

## Pipelines con generadores

Encadenar generadores da *pipelines* de datos que procesan ficheros de cualquier tamaño con memoria constante: cada línea atraviesa todas las etapas antes de leer la siguiente. Es el ejemplo del notebook del curso:

<RunCode
  title="Un pipeline que lee, parte, convierte y filtra"
  code={`
    import random

    # Creamos un CSV de prueba
    random.seed(0)
    with open("ventas.csv", "w") as f:
        f.write("item,cantidad,precio\\n")
        for _ in range(100_000):
            f.write(f"{random.choice(['Coffee', 'Tea', 'Cake'])},{random.randint(1, 5)},{random.choice([1.5, 2.0, 3.0])}\\n")

    print("Facturación de café:", sum(importes))   # solo aquí empieza a leerse el fichero
  `}

## Generadores para entrenar modelos

Keras entrena con lo que le des a `model.fit`: arrays enteros o un generador que entregue lotes `(X_lote, y_lote)`. Para imágenes en disco, el curso usa `ImageDataGenerator` con `flow_from_directory` (lee carpetas, una por clase) o `flow` (a partir de arrays), y le añade **aumentaciones**: giros, desplazamientos, zoom, brillo, volteos… cada época el modelo ve versiones un poco distintas de cada imagen, lo que reduce el sobreajuste.

    import numpy as np

    def batches(X, y, batch_size, rng):
        """Una época: lotes barajados; cada imagen se voltea en horizontal con probabilidad 0.5."""
        orden = rng.permutation(len(X))
        for inicio in range(0, len(X), batch_size):
            idx = orden[inicio:inicio + batch_size]
            Xb = X[idx].copy()
            voltear = rng.random(len(idx)) < 0.5
            Xb[voltear] = Xb[voltear][:, :, ::-1]
            yield Xb, y[idx]

    X = np.arange(10 * 2 * 3).reshape(10, 2, 3)
    y = np.arange(10)
    for Xb, yb in batches(X, y, 4, rng):

<Callout kind="real" title="Lo que se usa hoy en lugar de ImageDataGenerator">
`ImageDataGenerator` está **obsoleto** en Keras 3. Hoy se hace así:

- **Keras / TensorFlow**: `keras.utils.image_dataset_from_directory("datos/", image_size=(224, 224), batch_size=32)` para leer, y las aumentaciones como **capas** del modelo (`layers.RandomFlip`, `layers.RandomRotation`, `layers.RandomZoom`), que se activan solo al entrenar. Para un generador propio, se hereda de `keras.utils.PyDataset` (el antiguo `Sequence`) con `__len__` y `__getitem__`. Y `tf.data` para *pipelines* rápidos con `map`, `shuffle`, `batch` y `prefetch`.
- **PyTorch**: una clase `Dataset` (con `__len__` y `__getitem__`) y un `DataLoader` que hace lotes, baraja y carga en paralelo con `num_workers`; las aumentaciones, con `torchvision.transforms.v2`.

La idea es la misma de esta lección: los datos se producen por lotes y bajo demanda.
</Callout>

## Para llevar

- `yield` convierte una función en un generador: entrega un valor y se pausa con su estado.
- Los generadores son perezosos, pueden ser infinitos y usan memoria constante; se agotan tras un uso.
- Para un generador infinito: `while True` + `yield`; calcula `init + i * step` en vez de acumular.
- Encadenar generadores da *pipelines* que procesan ficheros de cualquier tamaño.
- Entrenar por lotes bajo demanda (con aumentación al vuelo) es la misma idea: hoy, `image_dataset_from_directory` + capas de aumentación, o `Dataset` + `DataLoader` en PyTorch.
