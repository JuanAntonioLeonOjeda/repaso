Las listas y los diccionarios de Python sirven para casi todo, pero hay problemas que piden una estructura concreta: deshacer pasos (pila), atender en orden de llegada (cola), sacar siempre el más urgente (cola de prioridad), buscar al instante (tabla hash) o recorrer relaciones (grafo). Elegir bien es lo que separa un script que tarda un segundo de uno que tarda una hora.

## El coste de cada operación

La pregunta es siempre la misma: **¿cuántos pasos hace la operación si los datos crecen?** Se escribe con la notación O grande: $O(1)$ es constante (no depende del tamaño), $O(n)$ crece con los datos y $O(\log n)$ casi no crece (con un millón de elementos, unos 20 pasos).

| Estructura | En Python | Lo rápido | Lo lento |
|---|---|---|---|
| Array dinámico | `list` | acceso por índice y `append`: $O(1)$ | `x in lista`, `insert(0, x)`, `pop(0)`: $O(n)$ |
| Pila (LIFO) | `list` con `append` / `pop` | meter y sacar del final: $O(1)$ | — |
| Cola (FIFO) | `collections.deque` | `append` / `popleft`: $O(1)$ | acceso por índice en medio |
| Cola de prioridad | `heapq` sobre una `list` | sacar el mínimo: $O(\log n)$ | buscar un elemento cualquiera |
| Tabla hash | `dict`, `set` | buscar, insertar, borrar: $O(1)$ de media | nada en orden |
| Grafo | `dict` de listas de vecinos | vecinos de un nodo | — |

<Callout kind="warn" title="La cola con una lista es lenta">
`lista.pop(0)` desplaza todos los elementos una posición: con una cola de un millón de tareas, cada extracción mueve un millón de elementos. `deque.popleft()` es $O(1)$. Para colas, siempre `deque`.
</Callout>

## Cola de prioridad: siempre el más pequeño

Un *heap* mantiene una lista organizada de forma que el **mínimo está siempre en la posición 0**, y meter o sacar cuesta $O(\log n)$. Es lo que usan los planificadores de tareas, el algoritmo de Dijkstra y la búsqueda A*.

```python
import heapq
tareas = []
heapq.heappush(tareas, (2, "entrenar"))      # (prioridad, tarea): se compara la tupla
heapq.heappush(tareas, (1, "limpiar datos"))
heapq.heappop(tareas)                         # (1, 'limpiar datos')
heapq.nsmallest(3, numeros)                   # los 3 menores sin ordenar todo
```

    import heapq

    def top_k(flujo, k):

## Tabla hash: buscar sin recorrer

`dict` y `set` son **tablas hash**: Python calcula `hash(clave)`, lo convierte en una posición de un array y guarda allí el valor. Para buscar, repite el cálculo y va directo: no recorre nada. Por eso las claves deben ser **inmutables** (si la clave cambiara, su hash cambiaría y no se encontraría) y por eso `x in set` es instantáneo y `x in list` no.

<CodeExercise

    print(eliminar_duplicados(["b", "a", "b", "c", "a"]))

  solution={`
    def eliminar_duplicados(lista):
        vistos = set()
        resultado = []
        for x in lista:
            if x not in vistos:
                vistos.add(x)
                resultado.append(x)
        return resultado

    print(eliminar_duplicados(["b", "a", "b", "c", "a"]))
  `}
  hints={[

    "if x not in vistos: vistos.add(x); resultado.append(x)",

  check={`

## Grafos: relaciones

Un grafo son nodos unidos por aristas: ciudades y carreteras, usuarios y amistades, páginas y enlaces. En Python, lo más práctico es una **lista de adyacencia**: un dict que a cada nodo le asocia sus vecinos. Para encontrar el camino con menos saltos entre dos nodos se usa la **búsqueda en anchura** (BFS), que explora por capas con una cola.

  solution={`
    from collections import deque

    red = {
        "Valencia": ["Madrid", "Barcelona", "Alicante"],
        "Madrid": ["Valencia", "Sevilla", "Bilbao"],
        "Barcelona": ["Valencia", "Bilbao"],
        "Alicante": ["Valencia", "Murcia"],
        "Murcia": ["Alicante", "Sevilla"],
        "Sevilla": ["Madrid", "Murcia"],
        "Bilbao": ["Madrid", "Barcelona"],
    }

    def camino_mas_corto(grafo, origen, destino):
        cola = deque([[origen]])
        visitados = {origen}
        while cola:
            camino = cola.popleft()
            nodo = camino[-1]
            if nodo == destino:
                return camino
            for vecino in grafo[nodo]:
                if vecino not in visitados:
                    visitados.add(vecino)
                    cola.append(camino + [vecino])
        return None

    print(camino_mas_corto(red, "Barcelona", "Sevilla"))
  `}
  hints={[
    "Una cola FIFO saca por la izquierda: popleft().",
    "Lo que se encola es el camino hasta el vecino: el camino actual más el vecino.",
    "cola.append(camino + [vecino])",
  ]}
  check={`
    c = camino_mas_corto(red, "Barcelona", "Sevilla")
    assert c is not None and c[0] == "Barcelona" and c[-1] == "Sevilla", "El camino debe ir de Barcelona a Sevilla"
    assert len(c) == 4, f"El camino más corto tiene 3 saltos (4 ciudades) y el tuyo tiene {len(c)} ciudades: {c}"
    assert all(b in red[a] for a, b in zip(c, c[1:])), "Cada paso del camino debe ser una conexión del grafo"
    assert camino_mas_corto(red, "Murcia", "Murcia") == ["Murcia"], "De un nodo a sí mismo el camino es solo ese nodo"
  `}
>
Completa la búsqueda en anchura. Como explora por capas, el primer camino que llega al destino es el de menos saltos.
</CodeExercise>
