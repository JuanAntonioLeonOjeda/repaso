Todo en Python es un objeto: un número, una lista, una función, un `DataFrame`, un modelo de scikit-learn. Cuando escribes `modelo.fit(X, y)` estás llamando a un **método** de un objeto que guarda **datos** (los coeficientes aprendidos). Saber escribir tus propias clases te permite leer el código de las librerías y empaquetar tus modelos, *datasets* y *pipelines* de la misma forma.

## Clase, objeto, self

Una **clase** es una plantilla; un **objeto** (o instancia) es algo construido con ella.

```python
class Empleado:
    empresa = "VIU"                      # atributo de CLASE: compartido por todos

    def __init__(self, nombre, salario): # constructor: se llama al crear el objeto
        self.nombre = nombre             # atributos de INSTANCIA: uno por objeto
        self.salario = salario

    def subir_sueldo(self, cantidad):    # método: función que recibe el objeto como self
        self.salario += cantidad

ana = Empleado("Ana", 30000)
ana.subir_sueldo(500)                    # equivale a Empleado.subir_sueldo(ana, 500)
```

`self` no es una palabra reservada: es el nombre que, por convenio, se le da al primer parámetro, que es **el propio objeto**. Por eso `ana.subir_sueldo(500)` y `Empleado.subir_sueldo(ana, 500)` son lo mismo.

Cuando lees `ana.empresa`, Python busca primero en el objeto, luego en su clase y luego en las clases padre. Si **asignas** `ana.empresa = "otra"`, creas un atributo de instancia que tapa el de la clase solo para `ana`.

## Métodos especiales

Los métodos con doble guion bajo (*dunder*) hacen que tus objetos se comporten como los nativos: `__repr__` decide cómo se imprimen, `__eq__` qué significa `==`, `__add__` qué hace `+`, `__len__` qué devuelve `len()`, `__getitem__` qué hace `obj[i]`. ## Herencia

Una clase hija hereda todo de la madre y puede **extender** (añadir) o **reemplazar** (sobrescribir) métodos. `super()` llama a la versión de la madre, que es como se extiende sin copiar código.

```python
class Gerente(Empleado):
    def __init__(self, nombre, salario, equipo):
        super().__init__(nombre, salario)   # extiende: reutiliza el constructor del padre
        self.equipo = equipo

    def subir_sueldo(self, cantidad):       # reemplaza, pero reutiliza
        super().subir_sueldo(cantidad * 1.1)
```

### Clases abstractas

Una clase abstracta define **qué métodos deben existir** sin implementarlos, y no se puede instanciar. Es la idea detrás de las interfaces de scikit-learn: todo estimador tiene `fit` y `predict`, y por eso un `Pipeline` puede encadenar cualquiera.

## Visibilidad: convenios, no muros

Python no tiene `private` de verdad. Hay convenios:

- `nombre`: público.
- `_nombre`: «interno, no lo toques desde fuera». Nadie te lo impide.
- `__nombre`: Python lo **renombra** a `_Clase__nombre` (*name mangling*) para evitar choques con subclases. Desde fuera, `obj.__nombre` da `AttributeError`, pero `obj._Clase__nombre` funciona.

Para validar al asignar, la herramienta idiomática es `@property`:

```python
class Temperatura:
    def __init__(self, celsius):
        self.celsius = celsius            # pasa por el setter

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, valor):
        if valor < -273.15:
            raise ValueError("por debajo del cero absoluto")
        self._celsius = valor
```

<Callout kind="real" title="dataclasses: clases de datos sin escribir el constructor">
Para clases que solo guardan datos (un registro, una configuración de entrenamiento), en el trabajo se usa `@dataclass`, que genera `__init__`, `__repr__` y `__eq__` por ti:

```python
from dataclasses import dataclass, field

@dataclass
class Config:
    lr: float = 1e-3
    epochs: int = 50
    capas: list[int] = field(default_factory=lambda: [64, 32])   # nunca un [] directo
```

Y para validar datos de entrada (una API, un fichero de configuración), **Pydantic**.
</Callout>

## Para llevar

- Una clase agrupa datos (atributos) y comportamiento (métodos); `self` es el propio objeto.
- Los atributos de clase se comparten: los mutables, en `__init__`.
- Los métodos *dunder* (`__add__`, `__eq__`, `__repr__`…) hacen que tus objetos funcionen con los operadores.
- `super()` reutiliza el código de la madre; una clase abstracta fija qué métodos deben existir.
- `_x` es un convenio; `__x` se renombra; `@property` valida al asignar; `@dataclass` para clases de datos.
