El autoencoder pone cada dígito donde le conviene y deja huecos por todas partes. El **autoencoder variacional** (VAE) arregla eso con dos cambios. El codificador ya no devuelve un punto, sino una **distribución** (una media y una varianza por dimensión). Y la pérdida castiga que esas distribuciones se alejen de una gaussiana estándar. El resultado es un espacio latente ordenado y sin huecos, del que se puede sacar un punto al azar y decodificarlo en un dígito.

## Codificar una distribución

```python
class VAE(nn.Module):
    def __init__(self):
        super().__init__()
        self.encoder, self.decoder = Encoder(2 * LATENT), Decoder()   # el codificador saca 4 números

    def forward(self, x):
        mu, logvar = self.encoder(x).chunk(2, dim=1)                   # media y log-varianza, (B, 2) cada una
        z = mu + torch.exp(0.5 * logvar) * torch.randn_like(mu)        # truco de la reparametrización
        return self.decoder(z), mu, logvar
```

Para cada dígito, el codificador dice: "su código está por aquí ($\mu$), más o menos con este margen ($\sigma$)". Durante el entrenamiento se **sortea** un punto de esa zona y se decodifica. Así el decodificador aprende que todos los puntos cercanos a $\mu$ deben dar un dígito parecido: no hay puntos aislados, hay regiones.

### El truco de la reparametrización

Sortear $z \sim \mathcal{N}(\mu, \sigma^2)$ dentro de la red es un problema: el backprop no sabe derivar a través de "sacar un número al azar". El truco es reescribir el sorteo para que el azar sea una entrada externa:

$$
z = \mu + \sigma \cdot \varepsilon, \qquad \varepsilon \sim \mathcal{N}(0, I)
$$

$\varepsilon$ no depende de ningún parámetro, y $z$ es una función derivable de $\mu$ y $\sigma$. Los gradientes llegan al codificador sin problema. Se usa `logvar` en vez de $\sigma$ porque puede ser cualquier número real, mientras que una desviación típica tiene que ser positiva: $\sigma = e^{\text{logvar}/2}$.

## La pérdida: reconstruir y ordenar

$$
\mathcal{L} = \underbrace{\text{BCE}(\hat{x}, x)}_{\text{reconstrucción}} + \underbrace{\text{KL}\big(\mathcal{N}(\mu, \sigma^2) \,\|\, \mathcal{N}(0, I)\big)}_{\text{orden en el espacio latente}}
$$

La divergencia KL entre dos gaussianas tiene fórmula cerrada. Por cada dimensión latente:

$$
\text{KL} = \tfrac{1}{2}\left(\sigma^2 + \mu^2 - 1 - \ln \sigma^2\right)
$$

Vale 0 solo si $\mu = 0$ y $\sigma = 1$. Empuja las medias hacia el origen y las varianzas hacia 1, así que los códigos de todos los dígitos acaban repartidos dentro de una gaussiana estándar, solapándose lo justo para no dejar huecos.

```python
def vae_loss(logits, x, mu, logvar):
    rec = F.binary_cross_entropy_with_logits(logits, x, reduction="sum") / len(x)
    kl = -0.5 * torch.sum(1 + logvar - mu.pow(2) - logvar.exp()) / len(x)
    return rec, kl
```

- **El VAE de Stable Diffusion** comprime cada imagen de 512 × 512 × 3 a un tensor latente de 64 × 64 × 4, y la difusión trabaja ahí (lección 8). Allí la KL lleva un peso muy pequeño: interesa sobre todo reconstruir bien.

## Para llevar

- El VAE codifica una gaussiana por imagen ($\mu$, $\sigma$) y decodifica un punto sorteado de ella.
- Reparametrización: $z = \mu + \sigma \varepsilon$, para que el gradiente atraviese el sorteo.
- Pérdida = reconstrucción + KL con $\mathcal{N}(0, I)$; la KL ordena el espacio latente y elimina los huecos.
- Genera sacando puntos de $\mathcal{N}(0, I)$; las muestras son variadas pero borrosas.
