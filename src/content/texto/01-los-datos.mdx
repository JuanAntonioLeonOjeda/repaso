Este tutorial hace con texto lo que el de visión hizo con imágenes: construir de principio a fin un modelo que lee una reseña de un producto, en español, y adivina **cuántas estrellas** le puso quien la escribió. ## El corpus

El **Multilingual Amazon Reviews Corpus** (MARC) recoge reseñas de Amazon de 2015 a 2019 en seis idiomas. La parte en español tiene **200.000 reseñas para entrenar, 5.000 para validar y 5.000 para test**, exactamente equilibradas: una quinta parte de cada número de estrellas. Cada ejemplo es el título y el cuerpo de la reseña, y su etiqueta, de 0 a 4 (1 a 5 estrellas).

```python
import json
from huggingface_hub import hf_hub_download

def load_split(split):
    path = hf_hub_download("mteb/amazon_reviews_multi", f"es/{split}.jsonl", repo_type="dataset")
    rows = [json.loads(line) for line in open(path, encoding="utf-8")]
    return [r["text"] for r in rows], np.array([r["label"] for r in rows])

train_texts, train_y = load_split("train")      # 200.000 textos y etiquetas 0–4
```

Son reseñas como estas:

| Estrellas | Reseña (inventada, del estilo del corpus) |
| :-------: | ----------------------------------------- |
| 1 | «No funciona. Llegó con la caja abierta y no enciende. Devuelto.» |
| 2 | «Pequeño para lo que anuncian. Cumple, pero no lo volvería a comprar.» |
| 3 | «Correcto. La calidad es la que esperas por ese precio, ni más ni menos.» |
| 4 | «Buen soporte, fácil de montar. Le quito una estrella porque faltaba un tornillo.» |
| 5 | «Perfecto, llegó antes de lo previsto y funciona de maravilla.» |

Son textos **cortos**: la mitad tiene 25 palabras o menos, el 90% no pasa de 59 y solo el 1% supera las 127. Eso importa más adelante, para decidir cuántos tokens procesa la red.

</Callout>

## Una etiqueta con orden

Hay dos formas de mirar las estrellas. Como **clases** (cinco categorías sin relación) o como un **número** (1 < 2 < 3 < 4 < 5). En este tutorial se entrenan clasificadores de cinco clases, que es lo habitual, pero se evalúan también como números, con el **error absoluto medio** (MAE): cuántas estrellas te equivocas, en media.

$$
\text{MAE} = \frac{1}{n} \sum_{i=1}^{n} |\,\hat{y}_i - y_i\,|
$$

Antes de entrenar nada conviene saber cuánto se consigue **sin saber nada**. Como las clases están equilibradas, predecir siempre lo mismo acierta un 20%.

## El fichero viene ordenado

Este es el error que casi se cuela en el script del tutorial. Para ajustar BETO (lección 6) se usan 40.000 reseñas de las 200.000. Lo natural es coger las primeras:

```python
train_texts[:40_000]          # ¡cuidado!
```

Pero el fichero de entrenamiento **viene ordenado por etiqueta**: las primeras 40.000 filas son todas de 1 estrella. Lo detectó la prueba rápida del script, cuando la regresión logística se quejó de que solo había una clase. La solución es barajar una vez, con semilla, antes de hacer cualquier subconjunto:

```python
def shuffled(texts, labels, seed=42):
    order = np.random.default_rng(seed).permutation(len(labels))
    return [texts[i] for i in order], labels[order]

train_texts, train_y = shuffled(train_texts, train_y)   # ahora sí: train_texts[:40_000]
```

<Callout kind="real" title="En el trabajo">
- **Comprueba la distribución de etiquetas de cada subconjunto** que entra en el entrenamiento, no solo la del dataset completo. Un `np.bincount(y_train)` antes de entrenar evita muchos disgustos.
- **Los datos reales no están equilibrados.** En Amazon, la mayoría de las reseñas son de 5 estrellas. Este corpus se equilibró a propósito; con datos reales tendrías que pensar en pesos por clase o en métricas que no premien predecir siempre la clase mayoritaria.
- **El texto va con su contexto.** El título de la reseña suele concentrar la opinión ("Dinero tirado", "Perfecto"). Aquí van juntos en un solo texto; en otros problemas, separar campos o añadir metadatos (categoría del producto, idioma) ayuda.
</Callout>
