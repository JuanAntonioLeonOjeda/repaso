## CIFAR-10

60.000 imágenes en color de **32×32 píxeles**, repartidas por igual en **10 clases**: 50.000 para entrenar y 10.000 para test. Es pequeño, pero no es fácil: a 32×32 un gato y un perro se parecen mucho, y un barco puede ocupar media foto o una esquina.

```python
from torchvision import datasets

raw = datasets.CIFAR10("data/", train=True, download=True)
print(raw.data.shape)      # (50000, 32, 32, 3): N, alto, ancho, canales (uint8, 0–255)
print(raw.classes)         # ['airplane', 'automobile', 'bird', 'cat', ...]
image, label = raw[0]      # una imagen PIL y un entero
```

Las imágenes vienen como `uint8` en formato **HWC** (alto, ancho, canal), que es como las guardan PIL, OpenCV y matplotlib. PyTorch, en cambio, quiere **CHW**: los canales primero. De eso se encarga `transforms.ToTensor()`, que hace dos cosas: pasa de HWC a CHW y divide entre 255 para dejar los valores en $[0, 1]$.

## Normalizar con las estadísticas de train

Además de pasar a $[0, 1]$, se resta la **media** y se divide entre la **desviación típica** de cada canal. Así cada canal queda centrado en 0 y con escala parecida, y los gradientes de la primera capa salen de un tamaño razonable desde el primer paso. Es la misma idea que el `StandardScaler` de supervisado, aplicada a cada canal de color.

```python
import torch

pixels = torch.tensor(raw.data, dtype=torch.float32) / 255   # (50000, 32, 32, 3)
mean = pixels.mean(dim=(0, 1, 2))   # una media por canal: tensor([0.4914, 0.4822, 0.4465])
std = pixels.std(dim=(0, 1, 2))     #                      tensor([0.2470, 0.2435, 0.2616])
```

Se calcula **solo con las imágenes de entrenamiento** y después se escribe como constante. (Estos valores son los de las 50.000 imágenes de train de CIFAR-10, antes de apartar la validación. Con 5.000 imágenes más o menos la media apenas cambia, pero en un proyecto propio calcúlalas con el train ya partido.) Esos son los números que verás en todos los tutoriales de CIFAR-10. Las transformaciones quedan así:

```python
from torchvision import transforms

CIFAR_MEAN = (0.4914, 0.4822, 0.4465)
CIFAR_STD = (0.2470, 0.2435, 0.2616)

eval_tf = transforms.Compose([
    transforms.ToTensor(),                      # HWC uint8 -> CHW float en [0, 1]
    transforms.Normalize(CIFAR_MEAN, CIFAR_STD) # (x - media) / std, canal a canal
])
```

## Train, validación y test

CIFAR-10 trae dos conjuntos, train y test. Para tomar decisiones (cuántas épocas, qué arquitectura, qué learning rate) hace falta un tercero: **validación**. Se saca de train, y el test no se toca hasta el final. Si eliges el modelo mirando el test, el test deja de ser una medida honesta.

```python
import torch
from torch.utils.data import DataLoader, Subset

def split_indices(n, n_val, seed=42):
    """El mismo reparto train/validación para todos los modelos, para que sean comparables."""
    perm = torch.randperm(n, generator=torch.Generator().manual_seed(seed)).tolist()
    return perm[n_val:], perm[:n_val]

train_full = datasets.CIFAR10("data/", train=True, transform=eval_tf)
test = datasets.CIFAR10("data/", train=False, transform=eval_tf)
train_idx, val_idx = split_indices(len(train_full), n_val=5000)   # 45.000 / 5.000

train_loader = DataLoader(Subset(train_full, train_idx), batch_size=128, shuffle=True, num_workers=4)
val_loader = DataLoader(Subset(train_full, val_idx), batch_size=128, shuffle=False, num_workers=4)
test_loader = DataLoader(test, batch_size=256, shuffle=False, num_workers=4)
```

Las tres piezas de PyTorch para los datos:

- **`Dataset`**: sabe cuántos ejemplos hay (`len`) y devuelve el ejemplo `i` ya transformado (`ds[i]`). `datasets.CIFAR10` es uno ya hecho; para tus propios datos escribirás una clase con `__len__` y `__getitem__`.
- **`Subset`**: un `Dataset` restringido a una lista de índices. Así se hace el split sin copiar imágenes.
- **`DataLoader`**: agrupa en lotes, baraja (`shuffle=True` solo en train) y prepara los lotes en paralelo (`num_workers`) mientras la GPU trabaja.

Cada lote sale con forma `(128, 3, 32, 32)` para las imágenes y `(128,)` para las etiquetas: enteros de 0 a 9, sin one-hot. Ya lo verás en la lección 2: `CrossEntropyLoss` los quiere así.

<Callout kind="real" title="En el trabajo">
- **Mira las imágenes antes de entrenar.** Una cuadrícula de 64 ejemplos con su etiqueta detecta etiquetas cruzadas, imágenes negras o duplicados en dos minutos. CIFAR-10 está limpio; tus datos no lo estarán.
- **Fija el split y guárdalo.** Con la semilla en el código, cualquiera que lo repita obtiene la misma validación, y dos modelos solo se comparan si se validan con las mismas imágenes.
- **Fotos de la misma fuente, en el mismo lado del split.** Si tienes varias fotos del mismo paciente, producto o cámara, se reparten por grupo (`GroupShuffleSplit`), como hiciste con los pacientes en el TFM. Si no, la validación se infla.
</Callout>

## Para llevar

- CIFAR-10: 50.000 + 10.000 imágenes de 32×32×3, 10 clases equilibradas.
- `ToTensor` pasa de HWC uint8 a CHW float en $[0, 1]$; `Normalize` resta la media y divide entre la std de cada canal.
- Las estadísticas se calculan **solo con train** y se aplican igual a validación, test y producción.
- Validación sacada de train con una semilla fija; el test, una vez y al final.
- `Dataset` da ejemplos, `Subset` hace el split, `DataLoader` hace lotes.
