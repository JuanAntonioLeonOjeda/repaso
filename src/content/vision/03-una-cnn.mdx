El MLP aplana la imagen y, para él, el píxel (0, 0) y el (0, 1) no tienen más relación que el (0, 0) y el (31, 31). Tiene que aprender por separado que un borde arriba a la izquierda y el mismo borde abajo a la derecha son lo mismo. Una **red convolucional** parte de dos ideas que una foto cumple: lo que importa es **local** (un borde, una textura, un ojo) y es **igual en cualquier sitio** de la imagen. Con esas dos ideas metidas en la arquitectura, la red necesita muchos menos parámetros y aprende mucho mejor.

## Un bloque convolucional

La CNN de este tutorial apila tres bloques iguales. Es el patrón de las VGG, que viste en la práctica: dos convoluciones 3×3 y un *max pooling*.

```python
def conv_block(c_in, c_out):
    return nn.Sequential(
        nn.Conv2d(c_in, c_out, kernel_size=3, padding=1),   # 3×3, misma altura y anchura
        nn.BatchNorm2d(c_out),
        nn.ReLU(),
        nn.Conv2d(c_out, c_out, kernel_size=3, padding=1),
        nn.BatchNorm2d(c_out),
        nn.ReLU(),
        nn.MaxPool2d(2),                                    # divide alto y ancho entre 2
    )
```

- **`padding=1` con un filtro 3×3** mantiene el tamaño: $(32 + 2 - 3)/1 + 1 = 32$. Así solo encoge el pooling, y la cuenta de formas es fácil.
- **`BatchNorm2d`** normaliza cada canal con la media y la varianza del lote, y luego aplica una escala y un desplazamiento que se aprenden. Estabiliza el entrenamiento y permite learning rates más altos. Por eso las convoluciones de una red con BN se pueden escribir sin sesgo (`bias=False`): el desplazamiento de la BN ya hace ese papel. Aquí se deja el sesgo por simplicidad.
- **Cada bloque divide el tamaño entre 2 y, a partir del segundo, dobla los canales** (3 → 32 → 64 → 128): la red cambia resolución espacial por "qué hay" (más mapas de características, más pequeños).

## La red completa, forma a forma

```python
class SmallCNN(nn.Module):
    def __init__(self, dropout=0.0):
        super().__init__()
        self.features = nn.Sequential(
            conv_block(3, 32),     # (B, 3, 32, 32)  -> (B, 32, 16, 16)
            conv_block(32, 64),    #                 -> (B, 64, 8, 8)
            conv_block(64, 128),   #                 -> (B, 128, 4, 4)
        )
        self.classifier = nn.Sequential(
            nn.Flatten(),          # (B, 2048)
            nn.Dropout(dropout),   # en la lección 5
            nn.Linear(128 * 4 * 4, 10),
        )

    def forward(self, x):
        return self.classifier(self.features(x))
```

Seguir la forma del tensor capa a capa es la habilidad más útil para depurar una CNN. El error típico, `mat1 and mat2 shapes cannot be multiplied`, casi siempre significa que el número de entradas de la `Linear` no cuadra con lo que sale del `Flatten`. El truco: pasa un tensor falso y mira.

```python
x = torch.randn(8, 3, 32, 32)
for block in model.features:
    x = block(x)
    print(tuple(x.shape))   # (8, 32, 16, 16)  (8, 64, 8, 8)  (8, 128, 4, 4)
```

**De 54% a 82,6%** con 5,5 veces menos parámetros. Ya en la primera época la CNN (64%) supera el mejor resultado del MLP. Cada época cuesta algo más del triple, porque una convolución hace muchas más operaciones por parámetro que una capa densa. Aun así, son 12 segundos por época.

El problema también se ve: la CNN **sobreajusta igual que el MLP**, solo que más arriba. La mejor validación llega en la época 6. Después, train sube hasta el 98% mientras la validación da tumbos entre el 79% y el 83%, y su pérdida sube de 0,53 a 0,79. La lección 5 se ocupa de eso.

<Callout kind="real" title="En el trabajo">
- **Casi nadie diseña su CNN desde cero.** Para un problema real se parte de una arquitectura conocida (ResNet, EfficientNet, ConvNeXt) y, sobre todo, de sus pesos preentrenados (lección 6). Escribir una CNN pequeña sirve para entender las piezas y para problemas muy alejados de las fotos normales.
- **`torchinfo.summary(model, input_size=(1, 3, 32, 32))`** imprime la forma y los parámetros de cada capa, como el `model.summary()` de Keras.
- **Global average pooling** (`nn.AdaptiveAvgPool2d(1)`) en lugar de `Flatten` hace la media de cada mapa: la red acepta cualquier tamaño de imagen y la capa final queda en 128 · 10 pesos. Es lo que usan las ResNet y tu TFM.
