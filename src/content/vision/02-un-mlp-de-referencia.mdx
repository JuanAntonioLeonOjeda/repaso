Antes de construir una red sofisticada conviene tener un **modelo de referencia** (*baseline*): algo sencillo que marque el listón. Sin él no sabes si tu CNN de 20 capas es buena o si cualquier cosa habría sacado lo mismo. Aquí el listón lo pone un MLP, la red de la práctica de MNIST, que trata la imagen como una lista de 3.072 números. De paso vas a escribir la pieza que se repite en todo PyTorch: el **bucle de entrenamiento**.

## Un modelo es un nn.Module

En PyTorch un modelo es una clase que hereda de `nn.Module`. Las capas se crean en `__init__` y el cálculo se escribe en `forward`:

```python
from torch import nn

class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Flatten(),                  # (B, 3, 32, 32) -> (B, 3072)
            nn.Linear(3 * 32 * 32, 512),
            nn.ReLU(),
            nn.Linear(512, 256),
            nn.ReLU(),
            nn.Linear(256, 10),            # 10 logits: sin softmax
        )

    def forward(self, x):
        return self.net(x)

model = MLP()
print(sum(p.numel() for p in model.parameters()))   # 1707274
```

Dos detalles que confunden al venir de Keras:

- **La última capa no lleva softmax.** Devuelve *logits*, puntuaciones sin normalizar. `nn.CrossEntropyLoss` aplica el softmax por dentro, de forma numéricamente estable. Si añades tu propio softmax, lo estarás aplicando dos veces, y la red entrena peor sin dar ningún error.
- **Las etiquetas son enteros**, no one-hot. `CrossEntropyLoss` equivale a la `SparseCategoricalCrossentropy(from_logits=True)` de Keras.

## El bucle de entrenamiento

Keras esconde el entrenamiento en `model.fit`. En PyTorch lo escribes tú. Son cinco líneas que repetirás en cada proyecto, también al entrenar un LLM:

```python
def train_one_epoch(model, loader, loss_fn, optimizer, device):
    model.train()                          # modo entrenamiento (importa con dropout y batch norm)
    total_loss, correct, seen = 0.0, 0, 0
    for x, y in loader:
        x, y = x.to(device), y.to(device)  # el lote, a la GPU (o a MPS en un Mac)
        logits = model(x)                  # 1. forward
        loss = loss_fn(logits, y)          # 2. pérdida
        optimizer.zero_grad()              # 3. borrar los gradientes del paso anterior
        loss.backward()                    # 4. backprop: calcula d loss / d parámetro
        optimizer.step()                   # 5. actualizar: w <- w - lr * gradiente (o Adam)
        total_loss += loss.item() * len(y)
        correct += (logits.argmax(dim=1) == y).sum().item()
        seen += len(y)
    return {"loss": total_loss / seen, "acc": correct / seen}
```

`loss.backward()` es la backpropagation que hiciste a mano en la asignatura: PyTorch va guardando las operaciones del forward en un grafo y luego aplica la regla de la cadena hacia atrás. Cada parámetro acaba con su gradiente en `p.grad`. Para ver que no hay magia, el ejercicio hace un paso completo a mano con NumPy, para un clasificador lineal con softmax: es la última capa de cualquier red.

## Entrenar el MLP

Con el bucle y una función de evaluación casi igual (sin `backward` ni `step`, en `model.eval()` y dentro de `torch.no_grad()`), entrenar es elegir pérdida, optimizador y épocas:

```python
device = torch.device("cuda" if torch.cuda.is_available() else "mps" if torch.backends.mps.is_available() else "cpu")
model = MLP().to(device)
loss_fn = nn.CrossEntropyLoss()
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)

for epoch in range(20):
    train = train_one_epoch(model, train_loader, loss_fn, optimizer, device)
    val = evaluate(model, val_loader, loss_fn, device)
    print(epoch + 1, train, val)
```

Dos cosas que verás repetidas en todo el tutorial:

- **El listón está en un 54%** de accuracy en validación (el azar sería un 10%). Encaja con lo que cuenta la lección de redes convolucionales de la asignatura sobre la práctica: el MLP se queda en torno al 50% en CIFAR-10.
- **A partir de la época 5 el MLP memoriza.** La pérdida de train sigue bajando, de 1,16 a 0,38, mientras la de validación sube, de 1,37 a 2,31. En train acierta el 87%; con imágenes que no ha visto, el 53%. Con 1,7 millones de parámetros y sin ninguna idea de lo que es una imagen, lo más fácil para él es aprenderse las 45.000 fotos de memoria.

<Callout kind="real" title="En el trabajo">
- **Primero un baseline, siempre.** Un MLP, una regresión logística sobre features o incluso "predecir siempre la clase mayoritaria". Si tu modelo caro no lo supera con claridad, algo va mal en los datos o en el código.
- **Sobreajusta un lote a propósito.** Antes de entrenar horas, entrena con un solo lote de 32 imágenes durante 200 pasos: la pérdida tiene que bajar casi a 0. Si no baja, el problema es un bug (etiquetas desalineadas, un softmax doble, un `zero_grad` olvidado), no la arquitectura.
- **AdamW con `lr=1e-3`** es el punto de partida por defecto. AdamW es Adam con el *weight decay* bien aplicado (lección 5). Ojo: aunque no lo escribas, PyTorch le pone `weight_decay=0.01` por defecto, así que este MLP ya lleva algo de regularización.
</Callout>

<Callout kind="idea" title="En Keras">

## Para llevar

- Un modelo es un `nn.Module`: capas en `__init__`, cálculo en `forward`.
- La salida son logits; `CrossEntropyLoss` aplica el softmax y quiere etiquetas enteras.
- El bucle: forward → pérdida → `zero_grad` → `backward` → `step`. Sin `zero_grad`, los gradientes se acumulan.
- El MLP marca el listón: un 54% en validación, y desde la época 5 sobreajusta.
