Hasta ahora los datos vivían en un `dict`: al reiniciar el servidor, desaparecen, y con varios procesos cada uno tendría el suyo. Las predicciones, los usuarios y los modelos registrados tienen que ir a una **base de datos**. En Python, lo estándar es **SQLAlchemy 2.0**: defines las tablas como clases y escribes las consultas en Python, y SQLAlchemy genera el SQL para SQLite, PostgreSQL o la que uses.

## Tablas como clases

```python
from sqlalchemy import String, create_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, sessionmaker

engine = create_engine("sqlite:///wine.db")     # en producción: "postgresql+psycopg://..."
SessionLocal = sessionmaker(engine)

class Base(DeclarativeBase):
    pass

class Prediction(Base):
    __tablename__ = "predictions"
    id: Mapped[int] = mapped_column(primary_key=True)
    alcohol: Mapped[float]
    quality: Mapped[int]
    model_name: Mapped[str] = mapped_column(String(50))

Base.metadata.create_all(engine)                # crea las tablas que falten
```

`Mapped[int]` es a la vez la anotación de tipo para tu editor y la definición de la columna (`NOT NULL`; `Mapped[int | None]` la haría opcional).

## Una sesión por petición

Una **sesión** es una conversación con la base de datos: agrupa cambios y los confirma (`commit`) o los descarta (`rollback`) juntos. La regla es **una sesión por petición**, abierta al empezar y cerrada al acabar. Es exactamente el patrón de la dependencia con `yield` de la lección anterior:

```python
def get_session():
    with SessionLocal() as session:   # el with la cierra siempre
        yield session

SessionDep = Annotated[Session, Depends(get_session)]
```

Y para devolver objetos de SQLAlchemy con un modelo de Pydantic, este necesita `from_attributes=True` (lee `p.quality` en vez de `p["quality"]`):

```python
class PredictionRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    alcohol: float
    quality: int
    model_name: str
```

## Consultar: select

Las consultas se construyen con `select()` y se encadenan filtros, orden y paginación. `session.scalars(stmt).all()` devuelve la lista de objetos:

```python
stmt = (
    select(Prediction)
    .where(Prediction.quality >= 6)
    .order_by(Prediction.id.desc())
    .offset(0)
    .limit(20)
)
predictions = session.scalars(stmt).all()
total = session.scalar(select(func.count()).select_from(Prediction))
```

## Cuando la base de datos dice que no

Una restricción `unique=True` hace que la base de datos rechace duplicados lanzando `IntegrityError`. Hay que capturarlo, deshacer la transacción y responder **409**. Comprobar antes con un `SELECT` no basta: entre la consulta y el `INSERT` puede colarse otra petición.

<Callout kind="real" title="Cómo se hace en el trabajo">
- **PostgreSQL** en producción, y SQLite (en memoria o en fichero) solo para tests o prototipos. Ojo: SQLite tolera cosas que PostgreSQL no; los tests de integración serios usan el mismo motor que producción (con Docker o `testcontainers`).
- Las tablas no se crean con `create_all`: se versionan con **Alembic**, que genera migraciones (`alembic revision --autogenerate`) y las aplica en cada despliegue. Cambiar el esquema sin migraciones es como no usar git.
- La lógica de acceso a datos suele ir en funciones o clases aparte (`crud.py`, *repositories*) que reciben la sesión, para que los endpoints queden finos y se puedan probar por separado.
- **SQLModel**, del mismo autor que FastAPI, une el modelo de SQLAlchemy y el de Pydantic en una sola clase. Es cómodo en proyectos pequeños; en grandes, mucha gente prefiere separarlos.
- Con endpoints `async def` se usa el motor asíncrono (`create_async_engine`, `AsyncSession`, drivers `asyncpg` o `psycopg`). Con el motor síncrono, los endpoints van con `def` (lección 10 explica por qué).
</Callout>

## Para llevar

- Tablas como clases con `Mapped[...]` y `mapped_column`; el `engine` habla con la base de datos.
- Una sesión por petición, como dependencia con `yield`.
- Crear: `add`, `commit`, `refresh`. Leer: `session.get` o `select(...)` con `where`, `order_by`, `offset`, `limit`.
- `ConfigDict(from_attributes=True)` para devolver objetos ORM con Pydantic.
- Las restricciones de la base de datos (`unique`) son la última palabra: captura `IntegrityError`, `rollback` y 409.
