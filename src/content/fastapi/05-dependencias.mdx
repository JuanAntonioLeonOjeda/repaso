Hay cosas que casi todos los endpoints necesitan: una sesión de base de datos, el usuario autenticado, los parámetros de paginación, el modelo cargado. Copiar ese código en cada función es pedir que un día una se quede sin comprobar el token. FastAPI lo resuelve con la **inyección de dependencias**: declaras *qué* necesita el endpoint y FastAPI se encarga de conseguirlo antes de llamarlo. Es la pieza que más distingue a FastAPI, y la que hace los tests fáciles.

## Depends

Una dependencia es una función normal. Sus parámetros se leen de la petición igual que los de un endpoint (query, cabeceras, cuerpo… o **otras dependencias**):

```python
from typing import Annotated
from fastapi import Depends, Query

def pagination(
    limit: Annotated[int, Query(ge=1, le=50)] = 10,
    offset: Annotated[int, Query(ge=0)] = 0,
) -> dict:
    return {"limit": limit, "offset": offset}

Pagination = Annotated[dict, Depends(pagination)]   # alias reutilizable

@app.get("/models")
def list_models(page: Pagination): ...

@app.get("/predictions")
def list_predictions(page: Pagination): ...
```

Fíjate en que `Depends(pagination)` recibe la función **sin llamarla**: es FastAPI quien la llama en cada petición. Y la documentación de `/docs` muestra `limit` y `offset` en los dos endpoints, porque FastAPI recorre las dependencias.

## Dependencias que protegen

Una dependencia puede **cortar la petición** lanzando `HTTPException`. Es la forma natural de proteger endpoints: si el endpoint la declara, no hay forma de olvidarse de comprobarlo.

Cuando el endpoint no necesita el valor (solo que la comprobación pase), se pone en el decorador: `@app.get(..., dependencies=[Depends(require_api_key)])`.

    from typing import Annotated

    import httpx
    from fastapi import Depends, FastAPI, Header, HTTPException, status

    app = FastAPI()

## Dependencias con yield

Para recursos que hay que **abrir y cerrar** (una sesión de base de datos, un fichero, una conexión), la dependencia usa `yield`: lo de antes se ejecuta antes del endpoint, el valor del `yield` es lo que recibe el endpoint, y el `finally` se ejecuta al final **aunque el endpoint falle**.

```python
def get_db():
    db = SessionLocal()
    try:
        yield db            # ← el endpoint trabaja con db
    finally:
        db.close()          # ← siempre se cierra
```

Dos detalles que conviene saber:

- Si dos dependencias piden la misma (el endpoint pide `get_db` y también `get_repo`, que a su vez pide `get_db`), **se ejecuta una sola vez por petición** y las dos reciben el mismo objeto. Es lo que quieres: una sesión por petición, compartida.
- Por defecto, el código después del `yield` se ejecuta cuando la respuesta **ya se ha enviado**. Si necesitas cerrar justo al terminar el endpoint, existe `Depends(get_db, scope="function")`.

## Cambiar dependencias en los tests

La gran ventaja: en los tests puedes **sustituir** cualquier dependencia sin tocar el código de la app, con `app.dependency_overrides`. El modelo real tarda en cargar o llama a un servicio de pago; en el test se cambia por uno falso que responde al instante y siempre igual.

<Callout kind="real" title="Cómo se hace en el trabajo">
- Las dependencias típicas de un proyecto: `get_db` (sesión), `get_current_user`, `require_role("admin")`, `get_settings`, `get_model`. Se agrupan en un `deps.py` y se exponen como alias (`CurrentUser = Annotated[User, Depends(get_current_user)]`).
- Si todos los endpoints de un grupo necesitan la misma comprobación, va en el router: `APIRouter(dependencies=[Depends(require_api_key)])` (lección 7).
- En los tests se limpian las sustituciones al acabar (`app.dependency_overrides.clear()`, normalmente en una fixture), para que un test no contamine al siguiente.
</Callout>

## Para llevar

- `Depends(funcion)` le pide a FastAPI que ejecute `funcion` antes del endpoint y le pase el resultado; sus parámetros se leen de la petición.
- Un alias `Annotated[tipo, Depends(...)]` evita repetir.
- Una dependencia que lanza `HTTPException` protege todos los endpoints que la usan.
- Con `yield`: abrir antes, cerrar en el `finally`. Se ejecuta una vez por petición aunque la pidan varios.
- `app.dependency_overrides` sustituye dependencias en los tests sin tocar la app.
