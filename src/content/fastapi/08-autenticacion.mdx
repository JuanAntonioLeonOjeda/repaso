Ahora mismo cualquiera puede pedir predicciones, borrar modelos o ver las predicciones de otros. Esta lección monta lo que tiene casi cualquier API: usuarios con **contraseña guardada como hash**, un **login que devuelve un token**, una dependencia que dice **quién hace la petición** y otra que comprueba **si puede hacerlo**. Vas a construir el token a mano para entender qué es; en el trabajo usarás una librería, pero sabrás qué hace.

## Contraseñas: nunca en claro

Las contraseñas no se guardan, ni cifradas: se guarda un **hash lento con sal**. Con el hash se puede comprobar si una contraseña es la correcta, pero no recuperarla. Y tiene que ser **lento a propósito** (bcrypt, argon2): un SHA-256 se calcula miles de millones de veces por segundo con una GPU, así que si te roban la base de datos, las contraseñas débiles caen en minutos.

```python
import bcrypt

hashed = bcrypt.hashpw(b"s3creta", bcrypt.gensalt())   # b"$2b$12$<sal><hash>"
bcrypt.checkpw(b"s3creta", hashed)                       # True
```

La **sal** (aleatoria, guardada dentro del propio hash) hace que dos usuarios con la misma contraseña tengan hashes distintos. El `12` es el coste: cada punto más duplica el tiempo.

## Tokens: qué es un JWT

Tras el login, el servidor entrega un **token** que el cliente manda en cada petición en la cabecera `Authorization: Bearer <token>`. El formato más usado es **JWT**: tres partes en base64url separadas por puntos.

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.eyJzdWIiOiJhbmEiLCJleHAiOjE3NjcyMjU2MDB9
.iwdlUIvd-Y4iqSsDMMJakK1MHDaGuwQKfN1p2CG5Dpo
```

Aquí está partido en tres líneas para que se vea; en realidad va todo seguido. Decodificado:

| Parte | Decodificada |
|---|---|
| cabecera | `{"alg":"HS256","typ":"JWT"}` |
| datos (*payload*) | `{"sub":"ana","exp":1767225600}` (1 de enero de 2026) |
| firma | `HMAC-SHA256(cabecera + "." + datos, clave)`, aquí con la clave `clave-del-servidor` |

Lo importante:

- Los datos **no están cifrados**: cualquiera puede leerlos decodificando el base64. No pongas nada secreto dentro.
- Lo que no se puede es **modificarlos**: la firma depende de los datos y de una clave que solo tiene el servidor. Si alguien cambia `"sub": "ana"` por `"sub": "admin"`, la firma deja de coincidir.
- `exp` (expiración, en segundos desde 1970) limita el daño si un token se filtra.

## El usuario actual como dependencia

Con todo lo anterior, la autenticación en FastAPI son dos piezas:

1. **Login**: comprueba usuario y contraseña y devuelve `{"access_token": ..., "token_type": "bearer"}`.
2. **`get_current_user`**: una dependencia que lee el token de la cabecera, lo verifica y devuelve el usuario, o responde **401**. `OAuth2PasswordBearer` lee la cabecera `Authorization: Bearer ...` por ti (y responde 401 si no está), y además hace que `/docs` muestre el botón *Authorize*.

Y una tercera para los **permisos**: `require_admin` depende de `get_current_user` y responde **403** si el usuario no tiene el rol.

<Callout kind="real" title="Cómo se hace en el trabajo">
- No escribas tu propio JWT en producción: usa **PyJWT** (`jwt.encode(payload, key, algorithm="HS256")`, `jwt.decode(token, key, algorithms=["HS256"])`), que además comprueba `exp`, `nbf` y los algoritmos permitidos. Fijar `algorithms` evita el ataque clásico del token con `"alg": "none"`.
- El login del ejercicio recibe JSON, así que el botón *Authorize* de `/docs` no funcionaría con él: ese botón envía un formulario. Para que funcione, el login recibe `form: Annotated[OAuth2PasswordRequestForm, Depends()]`, que necesita el paquete `python-multipart`.
- En muchas empresas no gestionas contraseñas: la identidad la lleva un proveedor (Auth0, Keycloak, Cognito, Entra ID) y tu API solo **verifica** sus tokens (firmados con RS256 y clave pública).
- Tokens de acceso **cortos** (15 min) y un *refresh token* para renovarlos; para servicio a servicio, **API keys** guardadas como hash y revocables.
- Siempre sobre **HTTPS**: un token interceptado vale lo mismo que la contraseña hasta que caduca.
</Callout>

## Para llevar

- Contraseñas: hash lento con sal (bcrypt, argon2), nunca en claro ni con SHA-256 a secas.
- Un JWT son datos legibles más una firma: nadie puede modificarlos sin la clave, pero todos pueden leerlos.
- `get_current_user` como dependencia: lee el token (`OAuth2PasswordBearer`), lo verifica y devuelve el usuario, o 401.
- Los permisos, otra dependencia encima: 403 si no tiene el rol.
- En producción, PyJWT o un proveedor de identidad, tokens cortos y HTTPS.
