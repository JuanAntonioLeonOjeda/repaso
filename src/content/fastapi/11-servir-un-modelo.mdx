Todo lo anterior converge aquí: una API que recibe las características de un vino y devuelve su calidad estimada, con un modelo de verdad entrenado con el dataset de vinos tintos de la asignatura de Supervisado. Servir un modelo tiene sus propios errores clásicos: cargarlo en cada petición, aceptar datos que el modelo nunca vio, predecir de uno en uno lo que podría ir en lote, o no saber qué versión del modelo dio cada respuesta.

## Entrenar y guardar (fuera de la API)

El entrenamiento **no** se hace en la API: es un script o un notebook aparte que deja un fichero con el modelo. Lo que se guarda es el **pipeline completo** (escalado incluido), para que en producción se aplique exactamente el mismo preprocesado que en entrenamiento.

<RunCode
  title="Entrenar y guardar el modelo"
  files={["winequality-red.csv"]}
  code={`
    import joblib
    import pandas as pd
    from sklearn.linear_model import Ridge
    from sklearn.metrics import mean_absolute_error
    from sklearn.model_selection import train_test_split
    from sklearn.pipeline import make_pipeline
    from sklearn.preprocessing import StandardScaler

    df = pd.read_csv("winequality-red.csv", sep=";")
    FEATURES = ["alcohol", "volatile acidity", "sulphates", "citric acid"]

    X_train, X_test, y_train, y_test = train_test_split(df[FEATURES], df["quality"], test_size=0.2, random_state=0)
    model = make_pipeline(StandardScaler(), Ridge()).fit(X_train, y_train)
    print("MAE en test:", round(mean_absolute_error(y_test, model.predict(X_test)), 3))

    # El artefacto: el pipeline y lo necesario para usarlo bien
    joblib.dump({"pipeline": model, "features": FEATURES, "version": "ridge-v1"}, "wine-v1.joblib")
    print(joblib.load("wine-v1.joblib")["version"])
  `}
/>

Un MAE de 0,48 significa que el modelo se equivoca en media medio punto de calidad. Con cuatro variables y una regresión lineal no da para más, pero para la API es igual: lo que importa ahora es servirlo bien.

## El endpoint de predicción

Las decisiones, una a una:

- **Cargar una vez**, en el `lifespan` (lección 7).
- **Esquema de entrada con los rangos de entrenamiento**: el modelo nunca vio un vino de 30 % de alcohol, y su predicción ahí no vale nada. Mejor un 422 que una respuesta inventada.
- **Los nombres de las columnas** tienen que coincidir con los del entrenamiento (`volatile acidity`, con espacio): el esquema de la API usa `volatile_acidity` y se traduce en un solo sitio.
- **Devolver la versión del modelo** en cada respuesta.
- `def`, no `async def`: `predict` de scikit-learn es CPU síncrona (lección 10).

## Predecir en lote

Un cliente que tiene que puntuar 80 vinos no debería hacer 80 peticiones: cada una paga la red, la validación y la llamada al modelo. Un endpoint de **lote** recibe una lista y llama a `predict` **una sola vez** con todas las filas, que es justo para lo que está optimizado scikit-learn (vectorizado con NumPy). Y la lista lleva un **máximo**, por la misma razón que la paginación.

<Callout kind="real" title="Cómo se hace en el trabajo">
- El modelo se versiona en un **registro de modelos** (MLflow, Weights & Biases, SageMaker) y la API carga una versión concreta por configuración. Promocionar un modelo es cambiar esa configuración, no el código.
- Los rangos del esquema salen de los datos de entrenamiento (el script de entrenamiento puede guardar `min` y `max` junto al modelo). Algunos equipos, en vez de rechazar, aceptan y marcan la respuesta como «fuera de distribución».
- Para cambiar de modelo sin riesgo: **shadow** (el nuevo predice en paralelo sin responder), **canary** (un 5 % del tráfico) o **A/B**. Todo eso solo es posible si cada respuesta lleva su `model_version`.
- Pickle y joblib ejecutan código al cargar: carga solo modelos de origen confiable. Para intercambiar modelos entre sistemas se usan formatos como ONNX o `skops`.
</Callout>

## Para llevar

- Entrenar fuera de la API; guardar el pipeline entero (con el preprocesado) y su versión.
- Cargar una vez en el `lifespan`; el esquema de entrada con los rangos de entrenamiento.
- `predict` de scikit-learn es CPU síncrona: endpoint `def`.
- Lotes: una llamada al modelo con todas las filas, con un máximo de tamaño.
- Cada respuesta con `model_version`, y cada predicción guardada con su entrada.
