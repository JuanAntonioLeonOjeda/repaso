Una API casi nunca devuelve siempre lo mismo: quiere *el modelo 3*, *las 20 primeras predicciones*, *solo los modelos en producción*. Esa información viaja en la petición de tres formas: en la **ruta**, en la **query** (`?limit=20`) y en las **cabeceras**. En FastAPI basta con declararlas como parámetros de la función, con su tipo, y FastAPI las lee, las convierte y las valida.

## Parámetros de ruta

```python
@app.get("/models/{model_id}")
def get_model(model_id: int):
    return {"id": model_id}
```

`{model_id}` en la ruta y `model_id: int` en la función son el mismo parámetro. El tipo no es decorativo: en la URL todo es texto (`"3"`), y FastAPI lo convierte a `int`. Si no puede (`/models/abc`), responde **422** sin ejecutar tu función.

## Parámetros de query

Cualquier parámetro de la función que **no** esté en la ruta se lee de la query string. Con valor por defecto es opcional; sin él, obligatorio.

```python
@app.get("/models")
def list_models(stage: str | None = None, limit: int = 10):
    ...
# GET /models?stage=prod&limit=5   → stage="prod", limit=5
# GET /models                      → stage=None,   limit=10
```

Para añadir restricciones se usa `Annotated` con `Query` (o `Path`, `Header`…). El tipo sigue siendo el primero; lo demás son metadatos que FastAPI usa para validar y documentar:

```python
from typing import Annotated, Literal
from fastapi import Query

def list_models(
    stage: Literal["dev", "prod"] | None = None,          # solo esos valores
    limit: Annotated[int, Query(ge=1, le=50)] = 10,        # 1 ≤ limit ≤ 50
    offset: Annotated[int, Query(ge=0)] = 0,
): ...
```

## El orden de las rutas importa

FastAPI prueba las rutas **en el orden en que las declaras** y se queda con la primera que encaja.

```python

def get_model(model_id: int): ...

@app.get("/models/latest")
def latest_model(): ...
```

## Cabeceras

Las cabeceras se declaran con `Header()`. FastAPI convierte el nombre: el parámetro `x_request_id` lee la cabecera `X-Request-ID` (guiones por guiones bajos, sin distinguir mayúsculas).

    from typing import Annotated

    import httpx
    from fastapi import FastAPI, Header

    app = FastAPI()

    @app.get("/whoami")
    def whoami(
        user_agent: Annotated[str | None, Header()] = None,
        x_request_id: Annotated[str | None, Header()] = None,

        return {"user_agent": user_agent, "request_id": x_request_id}

<Callout kind="real" title="Cómo se hace en el trabajo">
- **Ruta** para identificar un recurso (`/models/3`), **query** para filtrar, ordenar y paginar (`?stage=prod&limit=20`), **cabeceras** para lo transversal: autenticación, idioma, el id de traza de la petición.
- `Annotated[...]` es la forma recomendada desde FastAPI 0.95: la firma sigue siendo Python normal y puedes reutilizar el tipo (`Limit = Annotated[int, Query(ge=1, le=50)]`) en varios endpoints.
- Pon siempre las rutas fijas antes que las paramétricas, y nombra los ids con su tipo (`model_id: int`, o `UUID` si usas UUID): el 422 de `/models/latest` es un bug clásico.
</Callout>

## Para llevar

- Los parámetros de la función son la entrada: si están en la ruta, de la ruta; si no, de la query; con `Header()`, de las cabeceras.
- El tipo convierte y valida; si falla, 422 sin ejecutar tu código.
- `Annotated[tipo, Query(ge=..., le=...)]` añade restricciones, y `Literal[...]` limita los valores posibles.
- Rutas fijas antes que las que tienen parámetros.
- Todo listado lleva paginación con un máximo.
